### SQLite 查看/编辑器（新 crate `sqlite_viewer`，提交 4dfbe364ea）
- 文件：`crates/sqlite_viewer/{sqlite_viewer.rs, document.rs, db.rs, view.rs}`。
- 设计：
  - `document.rs`：`project::ProjectItem::try_open` 按扩展名（db/sqlite/sqlite3）+ 文件头 16 字节魔数
    `SQLite format 3\0` 判定；魔数不符则返回实体并在视图层提示"不是有效 SQLite 数据库"。
  - `db.rs`：rusqlite（0.32，bundled 编译 sqlite3.c，跨平台无系统依赖）。每次操作后台线程
    打开短连接（只读用 `SQLITE_OPEN_READ_ONLY`，写操作临时可写），`sqlite_master` 列出对象、
    PRAGMA table_info 取列、分页 LIMIT/OFFSET、UPDATE 写单元格（主键/rowid 定位，标识符与
    字面量转义防注入）。
  - `view.rs`：顶部表/视图切换按钮行 + 固定表头 + `uniform_list` 虚拟化数据行 + 分页栏；
    底部编辑行用 `Editor::single_line`，单击单元格懒建编辑器，失焦/Enter 提交写库后自动重载当前页。
  - 翻译 key：`sqlite_viewer.*` 16 个，zh-CN / en 双份。
- 接入：`crates/zed/src/main.rs` 调 `sqlite_viewer::init(cx)`；`crates/zed/Cargo.toml` 加依赖。
- 验证：`cargo test -p sqlite_viewer` 3 个单测通过（db 层 magic/读取/更新）；
  `cargo check -p sqlite_viewer -p zed` 与 `cargo clippy --all-targets` 零错误零警告；

## 已知问题与风险
- SQLite viewer 会话恢复（session restore）不支持：deserialize 直接报错，用户从项目面板重新打开。
- 无 INTEGER PRIMARY KEY 的表用 rowid 定位编辑；含重复行时按整行 IS 匹配 LIMIT 1，可能命中首行，
  无法区分完全相同的行——编辑准确性受限但不误伤（写入基于实际匹配行）。
- BLOB 列与 WITHOUT ROWID 表暂不支持单元格编辑（返回明确错误提示）。
- 打开文件时魔数校验在后台读前 16 字节，不整读大库，性能良好；但文件<16 字节报"过小"。

## 复现与运行
- `cargo test -p sqlite_viewer` 跑数据层单测。
- 运行 Zed 后从项目面板打开任意 `.db`/`.sqlite`/`.sqlite3` 文件即可进入 SQLite 查看/编辑视图。
